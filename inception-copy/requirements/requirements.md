## 1. Functional Requirements

### FR-1: 바둑판 숲 홈 화면

- **FR-1.1**: 홈 화면에 7×7 아이소메트릭 격자(바둑판)가 표시되어야 한다
- **FR-1.2**: 빈 칸을 클릭하면 나무 종류 선택 UI가 나타나야 한다
- **FR-1.3**: 나무 종류는 4가지(Ginkgo Tree, Cozy Sakura, Forest Gnome Oak, Celestial Star Tree) 중 선택할 수 있어야 한다
- **FR-1.4**: 심어진 나무를 클릭하면 해당 나무의 일기장 화면으로 전환되어야 한다
- **FR-1.5**: 나무는 일기 작성 일수에 따라 small/medium/large 세 크기로 표시되어야 한다
- **FR-1.6**: 나무 크기는 일기를 작성할 때마다 실시간으로 갱신되어야 한다

### FR-2: 일기 작성 및 저장

- **FR-2.1**: 나무 한 그루당 일주일(7일)짜리 일기장 리스트가 표시되어야 한다
- **FR-2.2**: 일주일의 기준은 나무를 심은(칸을 클릭한) 시점부터 7일이어야 한다
- **FR-2.3**: 작성 전 일기 칸에는 년월일(요일)만 표시되어야 한다
- **FR-2.4**: 사용자가 일기 내용을 작성하고 저장할 수 있어야 한다
- **FR-2.5**: 7일 모두 작성 시 large, 4~5일 작성 시 medium, 3일 이하 작성 시 small 나무가 되어야 한다
- **FR-2.6**: 일기 저장 시 성실도 검증을 통과해야 유효한 작성으로 인정되어야 한다
- **FR-2.7**: 성실도 검증 조건 — 공백 제거 후 최소 20자, 띄어쓰기 기준 최소 15어절, 고유 어절 비율 60% 이상을 모두 충족해야 한다
- **FR-2.8**: 성실도 검증 미통과 시 사용자에게 어떤 조건이 부족한지 안내하고 저장을 거부해야 한다

### FR-3: 월별 캘린더

- **FR-3.1**: 홈 화면 좌측 상단에 캘린더 열람 버튼이 있어야 한다
- **FR-3.2**: 버튼 클릭 시 화면이 전환되어 좌측에 월간 캘린더, 우측에 해당 월 일기 리스트가 표시되어야 한다
- **FR-3.3**: 캘린더에서 일기가 존재하는 날에는 감정 아이콘이 표시되어야 한다
- **FR-3.4**: 감정은 7가지(기쁨, 평온, 슬픔, 화남, 피곤, 설렘, 불안) 중 선택할 수 있어야 한다
- **FR-3.5**: 일기 작성 시 해당 날의 감정을 함께 기록할 수 있어야 한다

## 2. Non-Functional Requirements

### NFR-1: Performance

- **NFR-1.1**: 홈 화면(숲 격자)은 초기 로드 후 1초 이내에 모든 나무를 렌더링해야 한다

### NFR-2: Correctness

- **NFR-2.1**: 일기 작성 일수와 나무 크기의 매핑(7일=large, 4~5일=medium, 3일 이하=small)이 항상 정확해야 한다
- **NFR-2.2**: 저장된 일기 데이터는 브라우저를 닫았다 열어도 유지되어야 한다

### NFR-3: Testing

- **NFR-3.1**: 나무 크기 결정 로직을 단위 테스트로 검증해야 한다

### NFR-4: Security

- **NFR-4.1**: 로컬 스토리지에 저장되는 데이터는 XSS 공격에 대비하여 입력값을 새니타이즈해야 한다

### NFR-5: Maintainability

- **NFR-5.1**: 나무 종류·크기 임계값 등 설정값은 코드와 분리된 설정 파일/객체로 관리해야 한다
