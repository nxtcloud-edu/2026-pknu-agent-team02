## 1. Functional Requirements

### FR-1: 홈 화면 (나무 성장)

- **FR-1.1**: 홈 화면 중앙에 현재 키우고 있는 나무의 성장 이미지를 크게 표시할 수 있어야 한다
- **FR-1.2**: 현재 Day 진행 상태(예: Day 3 / 7)를 표시할 수 있어야 한다
- **FR-1.3**: "오늘 기록하기" 버튼을 제공하여 감정 기록 플로우로 진입할 수 있어야 한다
- **FR-1.4**: 오늘 기록을 이미 완료했다면 기록하기 버튼 대신 완료 상태를 표시해야 한다
- **FR-1.5**: 홈 화면 상단에 "마음 나무"(서비스명)와 설정 아이콘을 배치해야 한다
- **FR-1.6**: "오늘도 마음에 물을 주세요." 등 안내 문구를 나무 상단에 표시해야 한다
- **FR-1.7**: 나무 하단에 "기록 완료 후 7일차가 되면 가꿔낸 나무를 수확할 수 있습니다." 안내 문구를 표시해야 한다

### FR-2: 달력 위젯

- **FR-2.1**: 홈 화면 왼쪽 상단에 달력 위젯 아이콘을 배치하고, 누르면 달력 뷰가 열려야 한다
- **FR-2.2**: 달력에서 기록을 작성한 날짜에는 해당 감정에 대응하는 나무 아이콘(꽃/잎 등)을 표시해야 한다
- **FR-2.3**: 월 단위로 이전/다음 월 탐색이 가능해야 한다
- **FR-2.4**: 달력 상단에 "YYYY년 M월 · 일기" 형태로 현재 월을 표시해야 한다

### FR-3: 일기 리스트 위젯

- **FR-3.1**: 홈 화면 우측 상단에 리스트 위젯 아이콘을 배치하고, 누르면 해당 월의 일기 리스트가 열려야 한다
- **FR-3.2**: 리스트에는 날짜, 감정 아이콘, Moment 요약(한 줄)을 표시해야 한다
- **FR-3.3**: 현재 보고 있는 월에 해당하는 기록만 표시해야 한다

### FR-4: 감정 기록 플로우 (4단계)

- **FR-4.1**: Moment → Emotion → Reason → Insight 순서로 한 단계씩 진행하는 UI를 제공해야 한다
- **FR-4.2**: 상단에 진행 탭(Moment / Emotion / Reason / Insight)과 현재 단계 번호(예: 2/4)를 표시해야 한다
- **FR-4.3**: Moment — "오늘 가장 기억에 남는 순간은?" 텍스트 입력을 제공해야 한다
- **FR-4.4**: Emotion — 8가지 대표 감정(기쁨, 편안함, 뿌듯함, 슬픔, 불안, 화남, 아쉬움, 무덤덤함) 중 하나를 선택할 수 있어야 한다
- **FR-4.5**: Emotion — 감정 강도를 1~5단계 슬라이더로 선택할 수 있어야 한다 (1:약함 ~ 5:매우 강함, 3:보통)
- **FR-4.6**: Reason — "왜 그런 감정을 느꼈다고 생각해?" 텍스트 입력을 제공해야 한다
- **FR-4.7**: Insight — "이 경험을 통해 새롭게 알게 된 내 모습은?" 텍스트 입력을 제공해야 한다
- **FR-4.8**: 각 단계에서 "다음" 버튼으로 다음 단계로 이동할 수 있어야 한다
- **FR-4.9**: X 버튼으로 기록을 취소하고 홈으로 돌아갈 수 있어야 한다

### FR-5: AI 분석 (일일)

- **FR-5.1**: 4단계 기록 완료 시 AI에게 Moment, Emotion, Emotion Intensity, Reason, Insight를 전달하여 분석을 요청해야 한다
- **FR-5.2**: AI는 핵심 감정, 키워드(2~3개), 감정 발생 이유 요약, 자기이해 요약, 오늘의 메시지를 반환해야 한다
- **FR-5.3**: AI 응답은 JSON 형식으로 파싱 가능해야 한다
- **FR-5.4**: AI 분석 결과는 기록과 함께 영구 저장되어야 하며, 이후 해당 일기를 다시 열 때 재분석하지 않고 저장된 결과를 표시해야 한다

### FR-6: 오늘의 결과 화면

- **FR-6.1**: 기록 완료 후 "오늘의 정원" 결과 화면을 표시해야 한다
- **FR-6.2**: 오늘의 핵심 감정을 이모지 + 텍스트로 크게 표시해야 한다
- **FR-6.3**: AI가 추출한 키워드를 해시태그 형태로 표시해야 한다
- **FR-6.4**: "AI 마음 거울" 섹션에 AI의 분석 메시지를 표시해야 한다
- **FR-6.5**: 나무 성장 애니메이션 또는 이미지 전환(Day N → Day N+1)을 표시해야 한다
- **FR-6.6**: "나무가 한 단계 자랐어요" 메시지를 표시해야 한다
- **FR-6.7**: "홈으로" 버튼으로 홈 화면으로 돌아갈 수 있어야 한다

### FR-7: 나무 성장 시스템

- **FR-7.1**: 나무는 총 7단계로 성장해야 한다 (Day 1 씨앗 → Day 7 완성된 나무)
- **FR-7.2**: 각 Day별 시각적으로 구분되는 나무 이미지/SVG를 제공해야 한다
- **FR-7.3**: 사용자가 기록을 완료해야 다음 Day로 진행되어야 한다
- **FR-7.4**: 하루에 한 번만 기록 가능하며, 자정(00:00) 기준으로 리셋되어야 한다
- **FR-7.5**: 7일 연속이 아니어도 총 7회 기록 시 성장이 이어져야 한다 (건너뛴 날은 멈춤, 다시 기록하면 이어서 성장)

### FR-8: 7일 완료 · 나무 종류 결정

- **FR-8.1**: 7번째 기록 완료 시 일반 결과 화면 대신 "7 DAYS JOURNAL COMPLETED" 특별 완성 화면을 표시해야 한다
- **FR-8.2**: AI가 7일간의 기록을 종합 분석하여 8종 나무 중 하나를 결정해야 한다
- **FR-8.3**: 완성 화면에 결정된 나무 이름, 이미지, 주간 감정 분석 메시지, 주간 키워드를 표시해야 한다
- **FR-8.4**: "나무 수확하기" 버튼을 제공해야 한다
- **FR-8.5**: 수확 시 나무를 도감에 등록하고 새로운 나무 사이클(Day 1)을 시작해야 한다

### FR-9: 나무 8종 · 감정 1:1 매핑

- **FR-9.1**: 8가지 감정과 8가지 나무를 1:1로 매핑해야 한다
- **FR-9.2**: 매핑 예시 — 기쁨:벚나무, 편안함:소나무, 뿌듯함:참나무, 슬픔:버드나무, 불안:자작나무, 화남:단풍나무, 아쉬움:은행나무, 무덤덤함:대나무
- **FR-9.3**: 나무 결정은 7일간 가장 많이 등장한 감정만이 아니라, Reason과 Insight 내용까지 AI가 종합 분석하여 결정해야 한다
- **FR-9.4**: 어떤 감정이든 부정적인 나무로 연결하지 않아야 한다 — 모든 나무는 고유한 의미와 가치를 가진다

### FR-10: 나무 도감

- **FR-10.1**: 하단 네비게이션 "도감" 탭에서 도감 페이지를 제공해야 한다
- **FR-10.2**: 8종 나무를 카드 형태로 표시하고, 획득/미획득 상태를 구분해야 한다
- **FR-10.3**: 획득한 나무 카드에는 나무 이름, 이미지, 획득 날짜, 획득 횟수(×N)를 표시해야 한다
- **FR-10.4**: 미획득 나무는 "???"과 자물쇠 아이콘으로 잠금 표시해야 한다
- **FR-10.5**: 획득한 나무 카드 클릭 시 상세 페이지로 이동해야 한다

### FR-11: 나무 상세 (기록 아카이브)

- **FR-11.1**: 나무 상세 페이지에서 해당 나무의 이름, 영문명, 이미지, 수확일을 표시해야 한다
- **FR-11.2**: "7일간의 감정 기록" 섹션에 7일 각각의 날짜, 감정, 기록 완료 상태를 리스트로 표시해야 한다
- **FR-11.3**: "주간 감정 총평" 섹션에 AI의 주간 분석 메시지와 키워드를 표시해야 한다
- **FR-11.4**: 각 날짜 클릭 시 해당 일의 Moment, Emotion, Reason, Insight, AI 키워드, AI 요약을 확인할 수 있어야 한다

### FR-12: 하단 네비게이션

- **FR-12.1**: 홈, 기록, 도감 3개의 탭을 하단 네비게이션으로 제공해야 한다
- **FR-12.2**: "기록" 탭은 달력 + 일기 리스트를 보여주는 페이지로 이동해야 한다

### FR-13: 개발/시연용 테스트 기능

- **FR-13.1**: 개발 모드에서만 "다음 날로 이동" 버튼을 제공해야 한다
- **FR-13.2**: 개발 모드에서만 "테스트 데이터 일괄 생성" 기능을 제공해야 한다
- **FR-13.3**: 프로덕션 빌드에서는 테스트 기능이 노출되지 않아야 한다

## 2. Non-Functional Requirements

### NFR-1: Performance

- **NFR-1.1**: 페이지 전환 시 200ms 이내에 UI가 응답해야 한다
- **NFR-1.2**: AI API 호출 중에는 로딩 상태를 표시해야 한다

### NFR-2: Correctness

- **NFR-2.1**: 하루에 한 번만 기록이 저장되어야 하며, 자정 기준으로 정확히 리셋되어야 한다
- **NFR-2.2**: 7회 기록 완료 시 정확히 한 번만 나무 완성 프로세스가 실행되어야 한다
- **NFR-2.3**: 로컬스토리지 데이터가 유실되지 않는 한 기존 기록이 보존되어야 한다

### NFR-3: Testing

- **NFR-3.1**: 개발 모드의 테스트 기능(다음 날 이동, 데이터 생성)으로 전체 플로우를 검증할 수 있어야 한다

### NFR-4: Security

- **NFR-4.1**: LLM API 키는 클라이언트에 노출되지 않도록 서버사이드 또는 환경변수로 관리해야 한다

### NFR-5: Maintainability

- **NFR-5.1**: 나무 종류, 감정 목록 등 설정값은 상수 파일로 분리하여 변경 시 한 곳만 수정하면 되도록 해야 한다
- **NFR-5.2**: AI 프롬프트는 별도 파일 또는 상수로 분리해야 한다

## 4. Out of Scope (MVP)

- 회원가입 / 로그인 / 인증
- SNS 공유 기능
- 친구 기능 / 멀티유저
- 복잡한 통계 대시보드
- 이미지 생성 AI (나무 이미지는 미리 준비된 에셋 사용)
- 3D 나무 렌더링
- 여러 사용자 실시간 동기화
- 복잡한 알림/푸시 시스템
